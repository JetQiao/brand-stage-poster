# 更新已安装的 Skill

只有用户明确说“更新 brand-stage-poster 到最新版”等更新请求时才执行本流程。新建海报、编辑图片和导出尺寸时不检查或更新安装。用户已经授权更新且具备执行权限时直接推进，不另设确认步骤；本流程不假定 `skill-installer` 支持覆盖或自动更新。

## 先定位实际安装

1. 从宿主本次加载的 `SKILL.md` 路径确定安装目录，读取 `name` 和 `metadata.version`，记录更新前的版本与实际路径。解析符号链接时保留原有入口；不要把当前工作目录、同名开发仓库或下载目录当成安装位置。
2. 若发现多个同名副本，优先处理本次实际加载的一份，不同时更新所有副本，也不再安装一份。无法确定加载位置时只澄清目标目录。
3. 检查该目录是否为独立 Git 仓库根目录：`git rev-parse --show-toplevel` 返回的真实路径应与安装目录一致。位于其他项目 Git 仓库内的解压版仍按发布包安装处理；不要更新外层项目。
4. 清点本地修改、未知文件和任务文件。`output/`、`private/`、`.local/`、`dist/`、虚拟环境及宿主配置可能被 `.gitignore` 忽略，不能因状态显示干净就认定这些内容不存在。它们不属于更新覆盖范围。

## Git 安装

以下命令在已核实的安装目录执行，`skill_dir` 替换为实际绝对路径：

```bash
skill_dir="/absolute/path/to/brand-stage-poster"
git -C "$skill_dir" rev-parse --show-toplevel
git -C "$skill_dir" remote get-url origin
git -C "$skill_dir" branch --show-current
git -C "$skill_dir" status --porcelain=v1 --untracked-files=all
git -C "$skill_dir" ls-files --others --ignored --exclude-standard
```

- `origin` 必须确实指向官方 `JetQiao/brand-stage-poster`，例如 HTTPS 地址 `https://github.com/JetQiao/brand-stage-poster.git` 或对应 GitHub SSH 地址。地址不符时保留现状，说明来源差异，不擅自改远程。
- 仅在 `main` 分支、无暂存或未暂存修改、无未知未跟踪文件时继续。有本地修改或自定义分支时列出具体差异并保留原安装，不自动 stash、切分支、硬重置或清理文件。
- 被忽略的任务文件可以保留，但必须确认新版本将写入的路径不与其冲突；冲突时不覆盖，说明涉及的文件。

满足条件后获取官方主线，检查是否存在本地独有提交：

```bash
git -C "$skill_dir" fetch origin main
git -C "$skill_dir" rev-list --left-right --count HEAD...FETCH_HEAD
```

第一项大于零表示本地领先或分叉，保留本地提交并说明，不能以“更新”为由丢弃。两项均为零时已与主线一致。第一项为零且远端有新提交时，核对新增／变更路径与保留文件无冲突，再执行：

```bash
git -C "$skill_dir" pull --ff-only origin main
```

快进失败时保留当前内容并报告实际原因，不改用强制拉取。Git 路线跟随官方 `main`；完成后核验实际版本，不根据预期版本号宣称成功。

## ZIP／发布包安装

1. 读取[官方最新 Release](https://github.com/JetQiao/brand-stage-poster/releases/latest)，确定实际发布版本和对应 Skill 发布包，在技能扫描目录之外下载与暂存。不要猜测附件名，也不要将任意来源的同名包当成官方发布。
2. 若 Release 提供该包的 SHA256 文件或摘要，计算下载包的 SHA256 并逐字核对；不一致就停止使用该包。没有公布摘要时如实记录“发布方未提供 SHA256”，不能把自行计算的值称为已通过发布方校验。
3. 解压前检查包内路径，拒绝绝对路径、`..` 越界、指向包外的链接及异常文件；解压到独立暂存目录。找到真正包含 `SKILL.md` 的 Skill 根目录，核对名称、版本和相对引用，避免把压缩包外层目录嵌套进现有安装目录。
4. 用已安装版本对应的官方发布包比对本地官方文件，识别用户修改及额外文件。已知本地修改不覆盖；无法取得可靠旧版基准时说明无法区分本地修改，保留原安装。用户任务文件与本机配置不视为可删除的旧版文件。
5. 在所有技能扫描目录之外完整备份原安装，记录绝对路径与版本；不要在 `skills/` 内建立可被重复加载的备份副本。以新包的官方文件准备候选安装，将需要保留且不冲突的任务文件、用户文件及配置原样带入。出现同路径冲突或用户修改时保留原安装并列出差异，不覆盖处理。
6. 候选目录检查完成后，在原安装位置替换官方文件集；不直接在旧目录内嵌套解压，也不留下已移除的旧官方文件干扰新版本。替换失败则恢复备份，备份保留至用户自行清理。

## 完成与加载

再次读取原安装路径的 `SKILL.md`，核对 `name`、更新后版本、所需引用文件及 Git 状态或发布包来源。简短报告“原版本 → 新版本”、实际安装路径、备份位置（如有）与未处理的差异；若没有发生更新，明确说明已是最新或受阻原因。

磁盘更新不代表当前对话已重新加载。按宿主支持的方式刷新 Skill 或重新开启会话；未重新识别时重启宿主，并再次确认加载路径和版本，避免误用另一份同名副本。

若没有网络、文件写入或命令执行能力，给出对应安装方式的具体步骤、实际目标路径和官方发布链接，明确尚未更新，不声称已下载、校验或替换。

## 维护者版本规则

本次发布为 `1.1.1`，后续每次更新递增补丁号：`1.1.0 → 1.1.1 → 1.1.2`。同步 `SKILL.md` 的 `metadata.version`、实际存在的其他版本声明、发布包名称和 Release／标签；发布标签使用对应的 `v1.1.1` 等版本。

已经发布的标签和发布包保持不变；修正文档或实现后发布下一个补丁版本，不移动、覆盖或重写既有标签。用户更新时查找实际最新版本，不将本说明中的 `1.1.1` 当成固定下载目标。
